## 0 · Approach identity and output

- **0.1 Team ★** — RAG team silicon sample study. Members/creators: Farah Adeeba (University of Konstanz); Jing Ma (University of Konstanz); Marcia Ferreira Goncalves (Graphwise); Max Pellert (Barcelona Supercomputing Center). Corresponding contact: max.pellert@bsc.es.

- **0.2 Plain-language summary ★** — This Tier 3 entry combines direct treatment-effect forecasts from four model families: GPT-4o, GPT-5.4, Claude Sonnet 4.6, and Qwen3.8-27B. Each member provides a complete set of treatment-effect predictions for all benchmark interventions and outcomes using literature-conditioned retrieval. Qwen3.8-27B contributes two closely related HippoRAG runs that use the same corpus, graph index, checkpoint, embedding model, and prompts but differ in query-time retrieval scoring: one uses the stock HippoRAG ranking and one fuses the same graph ranking with matched dense passage retrieval. The two Qwen series are averaged first, after which the four model-level series are averaged with equal weight. All member series are calibrated using the same global factor before ensemble aggregation.

- **0.3 Submission tier & approach family ★** — Tier 3. Direct-forecast family; multi-model ensemble; literature-conditioned retrieval-augmented generation (RAG). No individual respondents or personas are simulated.

- **0.4 Pipeline diagram** — ordered steps from raw inputs to submitted file:
  1. Produce five complete Tier 3 member prediction files (`condition,outcome,ate`, 208 rows each):
     - Qwen3.8-27B + stock HippoRAG (`graph_weight = 1.0`);
     - Qwen3.8-27B + fused HippoRAG/dense retrieval (`graph_weight = 0.7`);
     - GPT-4o + parallel full-text RAG;
     - GPT-5.4 + parallel full-text RAG;
     - Claude Sonnet 4.6 + parallel full-text RAG.
  2. The two Qwen runs use the same 43-PDF corpus, the same Qwen3.8-built HippoRAG graph index, the same Qwen3.8-27B checkpoint, the same Qwen3-Embedding-4B embedding model, and the same prompts. Only query-time retrieval scoring differs:
     - stock run: use HippoRAG's PPR passage ranking as-is;
     - fused run: compute the same PPR ranking and the matched dense passage ranking over the same passage set, convert both score vectors to percentile ranks (PIT), and combine them as `0.7 × graph + 0.3 × dense`.
  3. Apply the common global calibration factor `b = 0.35` to each finalized member series.
  4. Run `code/scripts/02_ensemble_tier3.py`, which reads the five frozen calibrated member files from `code/results/`.
  5. Average the two Qwen series first:
     `Qwen_mean = (Qwen_stock + Qwen_g70) / 2`.
  6. Average the four model-level series with equal weight:
     `Final = (Qwen_mean + GPT4o + GPT5.4 + Claude) / 4`.
     Thus each Qwen run receives 12.5% of the final ensemble weight, while GPT-4o, GPT-5.4, and Claude each receive 25%.
  7. Save the final 208-row ensemble and copy the locked submission file to `predictions/team_28_T3_secondary-3_v1.csv`.

- **0.5 Coverage ★** — Full coverage confirmed: all 16 interventions × 13 outcomes = 208 ATE estimates, one row per intervention–outcome cell, with columns `condition,outcome,ate`.

## A · Scope of LLM use

- **A.1 Purpose** — LLMs are used upstream to generate the five member forecast series. GPT-4o, GPT-5.4, Claude Sonnet 4.6, and Qwen3.8-27B directly predict treatment effects under their respective RAG pipelines. For the two Qwen runs, Qwen3.8-27B is also used for HippoRAG's LLM-dependent graph construction/fact-reranking operations, while `Qwen/Qwen3-Embedding-4B` is used for passage/entity/fact/query embeddings. The final ensemble stage itself uses no LLM; it is a deterministic arithmetic aggregation of five frozen Tier 3 prediction files.

- **A.2 Degree of automation ★** — Fully automated at prediction and aggregation time. The final ensemble is generated by code from frozen member files with no human editing of individual prediction cells.

## F · Stochasticity and aggregation

- **F.1 Runs & seeds** — Stage 02 is fully deterministic given the five frozen member files. Member-generation stochasticity is inherited from the generating pipelines. The two final Qwen files are separate frozen runs with identical model/corpus/index/prompts but different retrieval scoring. Exact model-generation settings are fixed in the deposited code/logs for Qwen and in the primary repository for GPT-4o/GPT-5.4/Claude.

- **F.2 Aggregation rule** — Nested arithmetic mean:
  1. `Qwen_mean = (Qwen_stock + Qwen_g70) / 2`;
  2. `Final = (Qwen_mean + GPT4o + GPT5.4 + Claude) / 4`.

  Every model family therefore receives 25% total weight; each Qwen retrieval variant receives 12.5%. A flat five-file mean is implemented only as a sensitivity check and is not the submitted result. No performance weighting is used because held-out benchmark outcomes are unavailable, and no inverse-variance weighting is used because these member files contain point estimates without standard errors. Mean rather than median is used because the model-level ensemble has four continuous forecasts; a median would discard the outer two values.

## G · Validation & post-processing

- **G.1 Human validation** — None. No human reviewed or manually edited individual ensemble cells.

- **G.2 Post-processing** — Stage 02 reads five explicitly named, already-calibrated submission-format files and computes the nested mean cell by cell. The final benchmark submission is checked for complete 16 × 13 coverage, missing values, and duplicate cells. No ensemble cell is manually excluded.

- **G.3 Calibration corrections** — Yes. All five member series are calibrated with the same global factor `b = 0.35` before aggregation. With a common linear factor, averaging calibrated members is algebraically equivalent to averaging the corresponding raw files and multiplying the ensemble by 0.35 afterward. The calibration procedure was developed outside the Silicon Sample Benchmark target outcomes: the common pipeline documents an initial 0.56 heuristic from Ashokkumar et al. (2026), followed by external validation against published Voelkel et al. human data, with 0.35 selected close to the empirically best-fitting global factor. Full calibration provenance is documented in the Team 28 hosted-API supporting repository.

## J · Internal selection procedure

- **J.1 Design-space search †** — The final entry combines two structured variations:
  1. **Qwen retrieval variation:** stock HippoRAG versus PIT-normalized `0.7 × graph + 0.3 × dense`, while holding corpus, graph index, checkpoint, embedding model, and prompts fixed. Retrieval-only sweeps were used to verify that fusion materially changed top-k evidence and to compare alternative normalization rules without using target-study human outcomes.
  2. **Ensemble aggregation variation:** flat five-file mean versus nested model-balanced mean. The nested mean was chosen because a flat mean would give Qwen 40% total weight solely because it has two highly correlated retrieval variants. Mean was preferred to median, and no performance weights were fitted because benchmark ground truth was unavailable.

  The API-model member pipeline inherited its earlier RAG/full-text/prompt/calibration development from the hosted-API supporting entry. No Silicon Sample Benchmark target human outcomes were consulted.
